# Final AI History Cap Deployment Validation

- **Validation date:** 2026-11-03
- **Latest complete production batch:** 2026-11-03 20:56:18 UTC
- **Scope:** Read-only replay using the JavaScript AI Engine and production Supabase data. No code, database, or production settings were changed.

## Executive conclusion

**Do not approve a 150-candle cap for deployment based on this evidence.**

The actual JavaScript replay for the latest complete batch produced the same decision for all 102 markets as the stored production output, with maximum differences of 0.08 confidence points and 0.21 Market Strength points. This is encouraging for that batch only.

The 24-hour and 48-hour candidate batches cannot be treated as valid cap comparisons: the candle rows currently available for those historical timestamps do not match the row counts recorded by the original production runs. The 150-candle replays show substantial differences, but those differences cannot be attributed to the cap rather than changed or backfilled historical candle data. No complete decision batch exists near the 72-hour target.

Therefore, the evidence does **not** establish high confidence that reducing the cap to 150 preserves trading behavior across historical market conditions. Preserve the 1,000-candle cap until exact historical inputs can be replayed across multiple periods.

## Method and limitations

- Imported and called the production `analyzeMarket()` implementation from `lib/ai-engine.mjs` directly in Node.js; this was not a SQL reconstruction of the indicators.
- Scenario A is the persisted production decision, confidence, and Market Strength produced by the 1,000-cap engine at each stored batch timestamp. The original full candle arrays are not stored as immutable run inputs.
- Scenario B used the same batch's persisted market snapshot and run timestamp, with up to the newest 150 currently available candles per interval at or before that timestamp.
- The latest batch is the only result with near-parity against recorded 1,000-cap candle counts. Its 150-cap decision comparison is usable as a single-batch validation, not a multi-regime deployment guarantee.
- Historical 24h/48h candle counts are materially different from production records. Their numerical and decision deltas are exploratory only and cannot establish the isolated effect of reducing history.
- No complete 72h batch exists. The required multi-period validation is therefore incomplete.
- No test suite or build was run because no source code changed. The actual JavaScript replay was executed.

## Recommendation

**Do not reduce the production cap to 150 yet.** The latest batch is reassuring, but the available evidence is insufficient to claim high confidence across historical conditions. A valid go/no-go requires reproducible original candle inputs (or immutable input snapshots) and actual JavaScript 1,000-versus-150 replays for multiple complete batches, including the missing 72-hour window.
